# แผนยกระดับเว็บไซต์ JW Group ทั้งเว็บ

## เป้าหมาย
แก้ทั้งความน่าเชื่อถือของข้อมูลและความชัดเจนของดีไซน์ตามผล Impeccable /critique โดยให้ลูกค้าเข้าถึงธุรกิจที่ต้องการและผู้หางานสมัครได้สะดวก คงเอกลักษณ์ navy/orange และ Noto Sans Thai

## ข้อจำกัดที่ต้องรักษา
- ไม่ลบข้อมูล ข่าว รูปภาพ หรือประวัติเดิม
- ไม่แทนภาพจริงด้วยภาพสร้าง และไม่แต่งรางวัล รีวิว คำกล่าวผู้บริหาร หรือข้อมูลโครงการ
- คง URL ข่าวทั้ง 24 รายการและ SEO metadata เดิม การแก้ metadata ที่ผิด เช่นปี 1990 ต้องขออนุมัติเฉพาะพร้อมหลักฐานก่อน
- ไม่เปลี่ยนระบบจัดการข้อมูล การเข้าสู่ระบบ โครงสร้างข้อมูล หรือสัญญาการส่งข้อมูลโดยไม่อนุมัติแยก
- ไม่เผยแพร่ขึ้นเว็บจริงอัตโนมัติ

## ระยะ 1 — ความน่าเชื่อถือและช่องทางติดต่อ
**ทำได้หลังอนุมัติแผน โดยไม่เปลี่ยนข้อมูลในฐานข้อมูล**
- หยุดแสดงรีวิวตัวอย่างทั้ง 4 รายการบนหน้าสาธารณะ ใช้เฉพาะรีวิวที่ดูแลผ่านระบบ หากไม่มีให้ไม่แสดงส่วนนี้ ไม่ลบ records
- ใช้ลิงก์ Facebook/YouTube ที่มีในข้อมูลกลางแทนหน้าแพลตฟอร์มทั่วไป ไม่แสดงปุ่มบัญชีที่ไม่มีปลายทาง
- กรณีธุรกิจไม่มีเว็บไซต์ ให้ปุ่มระบุว่าติดต่อธุรกิจและไปหน้าติดต่อเดิม ไม่เดาเว็บไซต์
- ทำช่องทางโทรศัพท์บนหน้าเว็บให้ใช้ข้อมูลกลางเดียวกัน ไม่ใช้เบอร์ตัวอย่างระหว่างโหลด
- ไม่แสดงสถิติที่ยกจำนวนขั้นต่ำขึ้นเอง เช่น 17+ โครงการหรืออย่างน้อย 1 รางวัล ยุติการแสดงตัวเลขที่ยังไม่มีนิยามรับรอง โดยไม่แก้จำนวนใน records
- แยกข้อความแนะนำ Admin ออกจากหน้าสาธารณะ และให้ข้อมูลเดิมยังอ่านได้เมื่อภาพขาด

**รายการรอรับรองก่อนแก้ข้อเท็จจริง**
- ปีจดทะเบียน/เริ่มธุรกิจ และความหมายของ 30+ ปี เทียบกับ 2550 และ 1990
- จำนวนโครงการที่สำเร็จจริง จำนวนพนักงาน และการนับรางวัลแยกจากคะแนนรีวิว/การรับรอง
- ชื่อ ตำแหน่ง คำกล่าว และสายบังคับบัญชาของผู้บริหาร
- สถานะธุรกิจก่อสร้าง งาน 4 ตำแหน่ง และสวัสดิการ 6 รายการ
- อีเมลและโทรศัพท์ด้าน Privacy/PDPA รวมถึง LINE และบัญชีสังคมที่ว่าง
- สิทธิ์และแหล่งกำเนิดภาพเปิดหน้าหรือภาพสำรองที่ยังไม่ได้ยืนยัน

ข้อมูลที่รอรับรองจะถูกบันทึกเป็นรายการค้าง ไม่แทนด้วยข้อมูลสมมติ และไม่แก้เนื้อหาประวัติหรือ metadata โดยอัตโนมัติ

## ระยะ 2 — หน้าแรกและการนำทาง
- เอาการหน่วงเปิดหน้า 3 วินาทีที่ไม่สะท้อนการโหลดจริงออก โดยไม่แตะการเข้าสู่ระบบ
- ให้ชื่อ JW Group และขอบเขตธุรกิจเห็นชัดบนภาพเปิดหน้า คงสองทางเลือกสำรวจธุรกิจ/ติดต่อ
- คงวิดีโอเดิมและภาพสำรอง ทดสอบการโหลดช้า วิดีโอล้มเหลว มือถือ และลดการเคลื่อนไหว
- หากภาพสำรองยังไม่รับรอง ให้ใช้ภาพจริงจากข้อมูลเดิมที่บริษัทรับรองแล้ว ไม่สร้างภาพใหม่
- ลดการแย่งความสนใจระหว่างเมนู ปุ่มลอย และหน้าต่างคุกกี้ ไม่ตีความว่าต้องลบเมนูหลักซ้ำที่ยังพิสูจน์ไม่ได้
- ทำหน้าต่างคุกกี้กระชับบนมือถือ โดยรักษาการยอมรับ ปฏิเสธ และเลือกตั้งค่าอย่างเท่าเทียม

## ระยะ 3 — หน้าสาธารณะทั้งเว็บ
ใช้ Impeccable /shape เพื่อจัดลำดับเนื้อหา แล้ว /clarify, /layout, /harden และ /polish ตามปัญหาจริง ไม่เพิ่มลูกเล่นเพื่อการตกแต่งอย่างเดียว

| กลุ่มหน้า | สิ่งที่จะปรับ |
|---|---|
| หน้าแรก | ชื่อกลุ่ม → ธุรกิจ → หลักฐานที่รับรอง → ข่าว → ติดต่อ/ร่วมงาน |
| Business ทั้งห้า | ชื่อแบรนด์ ภาพจริง บริการ ผลงาน และปลายทางชัดเจน คง accordion/แกลเลอรี |
| About | ประวัติ วิสัยทัศน์ ทีม โครงสร้าง และรางวัลอ่านเป็นชุดเดียวกัน คงทุกหน้าเดิม |
| โครงสร้างองค์กร | ปรับความอ่านง่ายและเครื่องมือเดิม ไม่เปลี่ยนบุคคลหรือ parent records |
| News/รายละเอียด | ปรับลำดับอ่าน หมวด วันที่ และปุ่มแชร์ คงข้อความประวัติและ URL ทุกบทความ |
| Careers | เน้นงาน หน่วยธุรกิจ สถานที่ คุณสมบัติและสมัคร คงแบบฟอร์ม/การแนบไฟล์ |
| Contact | ข้อมูลกลาง ฟอร์มเดิม แผนที่ และปุ่มปลายทางจริง ไม่เพิ่มช่องเลือกธุรกิจที่ต้องเปลี่ยนสัญญาข้อมูล |
| Privacy/PDPA/Terms | อ่านง่ายและช่องทางที่รับรอง ไม่แต่งข้อความกฎหมาย |
| Sustainability/Premium search/404 | ปรับการนำเสนอและสถานะให้เข้าชุดโดยคงความสามารถ |
| Auth/Admin | ไม่ออกแบบใหม่หรือเปลี่ยนสิทธิ์ในงานนี้ ตรวจเพียงไม่ให้การปรับสาธารณะกระทบ |

ข้อความไทยทั่วไปปรับให้อ่านตรงและลดคำอ้างเกินจริง ส่วนชื่อเฉพาะ ข้อกล่าวทางสุขภาพ ประวัติ ข่าว และข้อเท็จจริงต้องรับรองก่อนแก้ ไม่ลบข่าวที่คล้ายกันเพียงเพราะชื่อซ้ำ

## ระยะ 4 — ตรวจรับก่อนส่งให้พิจารณาเผยแพร่
- ตรวจ desktop 1760×1091, 1280×1800, laptop 1440×900 และ mobile 390×844
- ตรวจเมนู ฟอร์ม validation แกลเลอรี ผังองค์กร คุกกี้ และปุ่มติดต่อด้วยคีย์บอร์ด
- ตรวจซูม 200% ลดการเคลื่อนไหว ภาพสำรอง เครือข่ายช้า และข้อความไม่ล้น
- ตรวจภาษาไทย/อังกฤษและความต่อเนื่องของอีกสี่ภาษา ไม่อ้างว่าเนื้อหาทุกภาษารับรองแล้ว
- เปิดข่าวเดิมครบ 24 URL และเทียบ canonical/title/description ไม่เปลี่ยนจากงานดีไซน์
- ทดสอบส่งแบบฟอร์มจริงและอ่านผลกลับเฉพาะเมื่อได้รับอนุญาตให้สร้างข้อมูลทดสอบและส่งอีเมล ไม่ใช้ข้อความหรือเรซูเม่ของบุคคลจริง
- รายงานข้อมูลที่ยังรอรับรองและข้อจำกัดการทดสอบ ไม่มีการ publish อัตโนมัติ

## รายละเอียดทางเทคนิค
- ยึด semantic tokens ใน `src/index.css` และ shared Button; scope `.home-page`, `.public-page`, `.corporate-page`, `.org-page` ตามเดิม
- ไฟล์หลัก: `Index.tsx`, `Navbar.tsx`, `Footer.tsx`, `CookieConsent.tsx`, `Hero3DBackground.tsx`, `TestimonialsSection.tsx`, `AnimatedStats.tsx`, `CompanyTimeline.tsx`, `CorporateLayout.tsx` และหน้าสาธารณะที่เกี่ยวข้อง
- `App.tsx`/`Loading.tsx` เปลี่ยนเฉพาะการหน่วงเข้าเว็บ ไม่เปลี่ยน auth
- ไม่แตะไฟล์ integration ที่สร้างอัตโนมัติ ไม่เขียน migration และไม่เปลี่ยน business keys ใน records
- ความเสี่ยงที่พบใน `send-contact-email` เช่นไม่ตรวจผลบันทึกและไม่แยกอีเมลส่งไม่สำเร็จ อยู่นอก presentation ต้องขออนุมัติแยก ไม่อ้างว่าส่งสำเร็จจากการตรวจ source
- เพิ่ม tests เฉพาะกฎข้อมูล/การแสดงผลที่เปลี่ยน และตรวจ flow จริงตามสิทธิ์ที่อนุมัติ

## เกณฑ์สำเร็จ
ไม่มีรีวิวตัวอย่างหรือปุ่มปลายทางว่างบนหน้าสาธารณะ ชื่อกลุ่มชัดตั้งแต่เปิดหน้า ทุกธุรกิจยังเข้าถึงได้ ภาพสำรองไม่หายเมื่อวิดีโอไม่ทำงาน ข่าว/SEO เดิมคงอยู่ และข้อมูลที่ยังไม่รับรองมีรายการรอชัดเจนก่อนพิจารณาเผยแพร่
